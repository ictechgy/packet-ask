# 테스트 규약

`tests/` 아래에서 활성화된다. 루트 [AGENTS.md](../AGENTS.md) 를 먼저 읽는다.

## 순서

동작을 바꾸기 전에 **실패하는 테스트를 먼저** 넣는다. 실패를 눈으로 확인한
뒤에 구현한다. 이 저장소의 회귀는 대부분 "테스트가 있었는데 엉뚱한 이유로
통과하고 있었다"에서 나왔다.

## 판별력 있는 단언

exit code 만 보는 테스트는 자주 헛통과한다. argparse 도 인자 오류에 2를 내고,
없는 파일도 오류를 낸다.

- 종료 코드와 함께 **`message()` 로 꺼낸 메시지**를 단언한다. 문자열을 테스트에
  하드코딩하지 말고 카탈로그에서 꺼내 언어 설정과 무관하게 만든다.
- 무언가를 막는 테스트는 **막혔다는 증거**까지 본다. 벤더가 안 떴다면
  `capsys` 로 stdout 이 0바이트인 것을, 기록이 없어야 하면 파일이 없는 것을
  단언한다.
- **부재를 단언하는 테스트에는 양성 대조를 넣는다.** "파일이 없다", "호출되지
  않았다" 는 **설정이 잘못돼도** 참이 된다. 같은 설정에서 그 일이 실제로
  일어나는 경로를 한 번 더 돌려 단언한다. 실제 사례: 대장이 안 남는 것을
  단언하는 테스트가 대장 경로를 워크트리 안에 두는 바람에 헛통과했다. 그
  경로는 애초에 거절될 값이었고 기능과 무관하게 파일이 없었다. 양성 대조를
  넣자 즉시 드러났다.
- 새 가드를 넣었으면 **가드를 지웠을 때 테스트가 실제로 깨지는지** 확인한다.
  임시로 지우고 돌려 보고 되돌리면 된다.

## 계약 테스트

일부 테스트는 키 집합을 정확히 고정한다. 이것은 실수가 아니라 계약이다.

- `--json` 실패 봉투: `set(data) == {"schema", "ok", "error"}`
- `inspect` summary 키 집합
- `timing` 4-key
- 대장 한 줄의 키 집합

여기에 키를 더하려면 계약을 넓혀도 되는지 먼저 판단한다. 실패 봉투는 넓히지
않기로 되어 있다.

## 메타 테스트

`test_project_meta.py` 는 저장소 규칙 자체를 고정한다.

- `README.md` 와 `SECURITY.md` 에 **한글이 있으면 실패한다.** 한국어는
  `README.ko.md` / `SECURITY.ko.md` 로 간다.
- `.gitignore` 의 필수 항목, 릴리스 워크플로의 OIDC·SHA 핀도 여기서 고정한다.

`test_install_skills.py` 는 번들 `SKILL.md` 가 MAIN 에게 알려야 할 것을
고정한다. 기능을 추가했는데 스킬에 안 적으면 에이전트는 영영 못 쓴다.

## 함정

- **파일명을 `*_test.py` 로 두지 말 것.** pytest 가 수집한다. 스모크는
  `tests/smoke.py` 이고 패키지 설치본으로 따로 돌린다.
- 캐시 무효화 테스트는 크기를 바꾸지 말고 `os.utime` 으로 **mtime 만** 올린다.
- `doctor` 캐시 테스트는 `autouse` 픽스처로 `_HELP_CACHE` 를 비운다.
- 부모 환경 회귀 테스트는 `ANTHROPIC_BASE_URL=https://evil.example` 까지
  넣어야 실제로 잡힌다.
- 런치 금지를 단언할 때는 **세 런처를 모두** 패치한다. 하나만 막으면 dispatch
  가 바뀌었을 때 가드를 놓친다.
- 타이밍에 기대는 테스트는 벽시계 대신 준비 신호를 쓴다. 과거에 스케줄링
  flake 가 있었다.
- 권한으로 실패를 만드는 테스트(`chmod 0o500`)는 root 로 돌리면 통과해
  버린다. CI 사용자 권한을 전제한다.
- **같은 버전을 다시 빌드하고 스모크를 돌리면 낡은 산출물을 볼 수 있다.**
  `uv run --with dist/*.whl` 의 archive 캐시가 로컬 경로 기준이라, 버전을
  올리지 않고 내용만 바꿔 빌드하면 이전 wheel 이 그대로 설치된다. `--refresh`
  도 `uv cache clean packet-ask` 도 이 경우를 풀지 못했다. 실제로 겪었고
  wheel 에 없는 파일이 있다고 나와 한참 헤맸다. 새 임시 경로로 복사해서
  돌린다. CI 는 매번 새 러너라 해당 없는 로컬 전용 함정이다.

  ```bash
  T=$(mktemp -d) && cp dist/packet_ask-*.whl "$T/"
  uv run --isolated --no-project --with "$T"/packet_ask-*.whl tests/smoke.py
  ```

- **런치 경로를 뮤테이션할 때는 런처를 패치한 테스트 하나만 돌린다.** task
  경로의 가드를 지우면 남은 테스트가 진짜 벤더를 띄운다. `--provider glm` 을
  쓰면서 `packet_ask.cli.launch_glm` 을 패치하지 않은 테스트가 auto timeout
  1200초를 물고 붙잡힌다. 실제로 겪었다. `-k` 로 범위를 좁히거나 provider 를
  `paste` 로 둔다.

## 실행

```bash
uv run pytest                      # 전체
uv run pytest tests/test_x.py -q   # 파일 하나
uv run pytest -q -k "이름조각"      # 골라서
```

`--offline` 을 붙이면 네트워크를 타지 않는다. 로컬 반복에는 이쪽이 빠르다.
