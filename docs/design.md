# packet-ask 설계

메인은 지금 세션을 돌리는 에이전트다. 서브만 스크럽된 패킷을 받는다.

실행형 내장: `paste`(출력만), `glm`, `kimi`, `claude`.
paste 전용 내장: `grok`, `agy`. 둘 다 계약을 확인했고 둘 다 격리 런치가
성립하지 않는다. `grok` 은 `--prompt-file`·`--tools`·`--sandbox` 를 갖췄지만 PATH 의
실행 파일이 실제 바이너리를 벤더 홈에서 찾고 전용 키를 받을 env 통로가 없어, 자식
HOME 을 격리 프로바이더 홈으로 바꾸는 이 도구의 런치 규약과 양립하지 않는다.
`agy` 는 태스크를 argv 로 넘겨야 해서 프로세스 목록에 보인다. 플래그 계약만 보고
승격하지 말 것.
사용자 `providers.toml` 은 paste 별명만 추가한다. 실행 파일은 지정할 수 없다.

## 목표

의도적으로 고른 패킷만 공식 도구에 넘긴다. 학습 금지·유출 없음을 보장하지 않는다.

> 이 도구는 의도적으로 보내는 범위를 줄입니다. 유출이 없음도, 학습되지 않음도 보장하지 않습니다.

## 실행 경계

1. 워크트리에서 스코프를 모은다.
2. 시크릿 리댁션 → 신원 스크럽 → 독립 패턴 재검증. 실패하면 벤더를 실행하지 않는다.
3. 0700 임시 패킷을 원본 레포가 아니라 OS 캐시에 만든다. cwd는 샌드박스가 아니다.
4. `doctor`는 지원 버전에서 필요하다고 본 help 플래그가 있는지 확인한다. 무도구를 수학적으로 증명하지 않는다. 불일치하면 실행하지 않는다.
5. Kimi는 TUI를 열지 않고 `kimi --quiet --agent-file`(tools: []) `--work-dir` 패킷으로 원샷한다.
6. 플래그를 확인하지 못하면 paste만 한다.
7. 사용자 개시, 한 건, 재시도 없음, 병렬 없음. task mode 는 `review` 와 `research` 둘뿐이고 문서화된 표면과 CLI 표면이 같아야 한다. review 는 --files/--diff/--staged/--unstaged 중 하나를 요구한다. research 는 로컬 diff 를 받지 않는다.
8. 출력은 untrusted 봉투로 반환하고 패킷을 삭제한다.
9. 런치는 고른 프로바이더만 `--help` 한다. help stdout/stderr는 합산 상한과 하나의 deadline 아래 읽고 실패 시 프로세스 그룹을 끝낸다. `doctor`는 카탈로그 전체를 보되 성공한 같은 바이너리는 canonical 경로·device·inode·mtime·크기로 캐시한다.
10. GLM/Claude 자식은 공식 bare mode, 빈 built-in tools, strict inline empty MCP config를 쓰고 claude.ai MCP·오토메모리·부가 트래픽·에러 리포팅을 끈다. 벤더가 값을 무시할 수 있으며 OS sandbox는 아니다.
11. 성공 시 stderr에 영수증과 밀리초 구간을 쓰고, `--json` 에 `timing` 을 넣는다. 비밀 값은 넣지 않는다.
12. 명시 파일·질문 stdin·git 출력은 예산까지만 읽는다. 최종 `packet.md` 전체가 `--max-bytes` 안에 있어야 한다.
13. 벤더 stdin/stdout/stderr를 하나의 deadline 아래 동시에 처리한다. stdout 선출력으로 stdin 쓰기와 timeout을 막지 못한다.
14. 벤더 출력의 터미널 제어문자를 제거한 뒤 전용 키를 다시 검사한다. receipt 경로는 JSON 이스케이프한다.
15. 프로바이더 프로필의 심링크와 Kimi 세션 정리 실패를 숨기지 않는다.
16. credential source는 `auto`/`env`/`keychain`/`prompt`만 허용한다. `auto`는 전용 env 다음 packet-ask canonical macOS Keychain만 보고 prompt하지 않는다.
17. 실제 선택된 key는 저장 위치와 무관하게 벤더 출력의 원문·터미널 정규화 결과 모두에서 반사 여부를 검사한다.
18. macOS Keychain 저장은 `command`(고정 `/usr/bin/security` 신뢰, background 사용)와 `prompt`(trusted app 없음, 매회 사용자 승인)를 구분한다. 둘의 위협 모델을 같은 것으로 주장하지 않는다.
19. worktree discovery, diff, packet-local `git init`은 같은 bounded Git runner를 써 deadline·출력 상한·interrupt group kill을 공유한다.
20. provider 성공 stdout과 timing은 packet cleanup 뒤에만 공개한다. 기존 실패가 있으면 cleanup 경고가 원래 종료 코드를 가리지 않는다.
21. 공개 redaction metadata는 허용된 음이 아닌 정수 count만 직렬화한다.
22. `Packet`은 렌더링 text/bytes/digest를 소유하고 receipt·launch가 재사용한다. user provider overlay는 canonical path·device·inode·mtime·size·언어로 캐시한다.
23. `--timeout` 생략 시 최종 packet bytes로 64KiB 이하 1200초, 128KiB 이하 1500초, 초과 1800초를 고른다. 명시값은 clamp하지 않는다.
24. receipt에 `timeout_seconds`/`timeout_source`/`timeout_applies`를 additive 공개하고 기존 `timing` 4-key 계약은 유지한다.
25. 새 packet은 directory advisory lock과 0600 lease marker를 process 동안 보유한다. 다음 실행은 current-user 0700 direct child 중 lock을 얻을 수 있고 marker가 24시간 지난 packet만 fd-relative로 비우며 marker는 마지막에 지운다.
26. task 범위 SIGTERM/SIGHUP은 각각 143/129 `SystemExit`로 바꾼다. spawn과 packet assignment 동안만 전달을 미루고 등록 직후 기존 BaseException 경로가 child group과 packet을 정리한다.
27. `--json` 실패는 같은 `packet-ask.v1`에 `ok: false`와 고정 code/kind/message만 넣는다. raw argv·예외 원문·경로·키·traceback은 넣지 않고 실제 exit code는 유지한다.
28. `inspect review|research`는 기존 scope·policy·redaction·budget·signal·cleanup 경계를 재사용하고 provider catalog/probe·credential·timeout·launch 없이 mode/selector/상대경로/count/bytes/digest만 공개한다.
29. builtin provider ID는 immutable adapter registry와 일치해야 한다. registry는 launch 함수 이름과 doctor 판정 종류만 코드로 보유하고 user alias는 adapter ID 없이 paste만 가능하다.
30. scrubbed 원문은 NFKC/Cf/dot/dash/decimal detection shadow에서 Unicode mailbox·phone을 추가 검사하되 shadow로 packet을 변형하지 않는다. 위치 mapping 없이 generic kind로 fail-close하고 Unicode 코드 operand+미인식 ASCII suffix는 오탐 완화를 위해 허용한다.
31. credential source는 immutable builtin backend registry의 env/keychain/prompt만 허용한다. auto 순서는 env→keychain으로 별도 고정하고 prompt를 포함하지 않으며 explicit source는 다른 backend로 fallback하지 않는다.
32. `_SECRET_VALUE_PATTERNS`는 primary scrub과 detection shadow verify가 공유한다. secret literal·URL userinfo·PEM header도 shadow에서 재검증하고 dotted 국내 mobile은 canonical scrub + mixed-separator fail-close로 처리하되 E.164 일반화는 별도다. dotted 후보의 왼쪽 경계는 숫자 바로 붙음만 자르고 점은 자르지 않는다. 점을 자르면 `v1.010.1234.5678`이 scrub·verify를 모두 통과해서 그대로 나갔다. 오른쪽 `(?!\d|\.\d)`는 유지한다. 번호 뒤에 점+숫자가 더 있으면 전화번호가 아니라 더 긴 dotted 식별자(OID·버전열)의 일부로 보고 보존하며, 그쪽까지 넓히면 식별자를 조각낸다. 그래서 `010.1234.5678.9012`와 `010.1234.5678.9`는 계속 두 단계 모두 통과한다. 보존 조건은 점+**숫자**이므로 `010.1234.5678.beta`는 번호로 보고 지운다. 왼쪽을 넓히면 후행 그룹이 없는 dotted 식별자(`1.2.010.1234.5678`)도 조각나는데, 이것이 의도 동작이고 테스트가 고정한다. 대가로 canonical이 아닌 dot-prefixed run(`1.010.1234.567`)은 scrub이 못 지우고 verify만 잡으므로 그 패킷은 못 나간다. mixed-separator fail-close와 같은 계열의 수용 절충이고 방향이 fail-closed다. 저장소 74개 파일을 두 패턴 세트로 돌려 신규 차단은 0건이었다.
33. Kimi 성공 output은 session cleanup 뒤에만 반환한다. provider/output-guard/SystemExit/KeyboardInterrupt가 먼저 실패한 경로에서는 cleanup PacketAskError를 고정 warning으로 강등하고 primary exception을 bare raise로 보존한다.
34. 공유 KIMI_CODE_HOME의 config→launch→session cleanup 전체를 0600 non-inheritable advisory lock으로 직렬화한다. 획득은 30초 상한이며 lock 획득 오류만 confinement로 변환하고 with 본문 예외는 재분류하지 않는다.
35. `--preflight-timeout`은 기본 30초 absolute monotonic Deadline을 만들고 real-fd question stdin·rev-parse·name-status·diff·packet git init이 공유한다. 각 Git 호출은 `min(shared, now+30s)`를 쓰며 file read/CPU 단계의 강제 preemption은 주장하지 않는다.
36. user alias label/note는 길이·UTF-8 byte 상한과 Cc/Zl/Zp 및 bidi Cf 거절을 적용하되 ZWNJ/ZWJ는 허용한다. research diff selector는 policy와 scope collector 양쪽에서 거절하고 cache OSError는 path 없는 confinement로 변환한다.
37. task와 inspect는 `PacketInputs`로 question/policy를 먼저 확정하고 공통 packet pipeline context가 worktree·scope·budget·cache/GC·build 및 success/failure cleanup을 소유한다. provider lookup과 공개 output은 context 밖/본문에서 기존 순서를 유지한다.
38. inspect `--breakdown`은 cached scrub 결과로 question/framing/item byte와 항목별 public redaction count만 additive 공개한다. task `--progress`는 opt-in 30초 heartbeat로 fixed phase/elapsed만 0초 writable check 뒤 stderr에 쓰고 provider 종료 시 join한다.
39. 성공 표면은 자신의 한계를 같이 공개한다. receipt 와 inspect summary 에 코드 상수 `GUARANTEES`(leakage/vendor_training/vendor_local_copy/cwd_sandbox/redaction/doctor/policy_gate/output_screen)를 additive 로 싣고, 사람이 읽는 receipt 한 줄에는 고정 축약을 붙인다. 산출값이 아니라 상수다. 부정문 키는 그래서 과잉 약속으로 드리프트하지 않는다. 기전 존재를 주장하는 redaction/doctor/policy_gate/output_screen 는 상수가 기전보다 오래 살아남으면 기계 판독 가능한 거짓이 되므로 실제 동작 테스트에 묶는다. 목록은 전부가 아니다. 27의 실패 봉투는 넓히지 않는다. 실패는 아무것도 보내지 않은 상태라 상쇄할 잘못된 안심이 없다. 한 줄에 싣는 키는 `_RECEIPT_LINE_KEYS` 가 선언하고 값은 상수에서 조립한다. 줄에 문자열을 직접 적으면 `GUARANTEES` 값이 바뀌어도 옛 값을 말한 채 남는다. 규칙은 **기전 서술 키(doctor/policy_gate/output_screen)를 뺀 나머지를 모두 싣는다**다. 그 셋은 무슨 기전이 있는가를 말하고 각각 동작 테스트에 묶여 있으며, 나머지는 전부 한계 서술이다. 테스트가 그 여집합을 이름으로 고정하므로 키를 추가하는 사람은 둘 중 어디에 넣을지 고르지 않으면 깨진다. `redaction` 은 양쪽에 속한다 — 값 `denylist` 자체가 한계 서술이다. 보강 근거로 SECURITY 의 does-not-do 절 길이를 쟀고, `vendor_local_copy` 절이 한계 키 중 가장 긴데 줄에는 빠져 있었다. 문서가 길게 부정하는 것일수록 성공 표면에서 빠지면 성공 신호가 더 크게 읽힌다. 수치 자체는 코드와 문서에 박지 않는다. SECURITY 가 바뀌면 조용히 썩는다. inspect 는 벤더를 띄우지 않아도 같은 상수를 그대로 싣는다. 이 객체는 한 번 실행의 측정이 아니라 도구의 한계 목록이고, 표면별로 키 집합이 갈라지면 additive 계약이 무의미해진다. 읽는 쪽은 그 표면의 런치 상태와 같이 읽는다.
40. 영수증은 stderr 로 한 번 나가고 사라진다. 스킬 배포에서 스코프를 고르는 것은 MAIN 이므로 사람이 나중에 무엇이 나갔는지 물을 표면이 없다. `PACKET_ASK_LEDGER` 가 설정되면 런치 전에 append-only JSONL 한 줄을 남긴다. 절대 경로만 받고 워크트리 안·심링크·다른 uid 소유·비정규 파일을 거절한다. 워크트리 검사는 device·inode 조상 탐색이라 대소문자 비구분 파일시스템에서 뚫리지 않는다. O_APPEND·O_NOFOLLOW·O_NONBLOCK 으로 열고 이미 있던 파일이어도 첫 쓰기 전에 0600 을 강제하며 부분 쓰기를 끝까지 채운다. 기록은 egress 지점 도달을 뜻하지 전달 확인이 아니다. 질문과 파일 본문은 기록하지 않는다. 기록에 실패하면 벤더를 실행하지 않는다. 조용히 빠뜨리는 대장은 없느니만 못하다.
41. 설계는 사용자가 고른 패킷이지만 스킬 배포에서 `--files` 를 고르는 것은 MAIN 이다. 워크트리 루트의 사람이 커밋한 `.packet-ask-surface` 가 있으면 명시 파일 목록이 선언된 경로 접두어 안에 있어야 한다. 없으면 강제는 꺼져 있다. 매칭은 문자열이 아니라 경로 구성요소 단위이고, 절대 경로·상위 참조·글롭·제어문자·심링크·빈 선언을 거절한다. `--outside-surface` 로 우회할 수 있으나 receipt·inspect·ledger 에 `overridden` 으로 남는다. diff 경로도 검사한다. `--diff <임의 ref>` 는 워크트리 흔적 없이 과거를 꺼낼 수 있어 면제 논거가 성립하지 않는다. 하드링크와 diff 내용 주입은 잡지 못하며 선언은 경로에 관한 것이지 내용 보증이 아니다. 이것은 유출 방지 allowlist 가 아니라 공개 범위 선언이며, 에이전트가 범위를 넓히려면 커밋된 파일을 고쳐야 해서 그 편집이 git status 나 새 커밋으로 기존 사람 리뷰 루프 위로 올라온다는 것이 유일한 기제다.

42. `doctor` 는 성공 신호만 내는 표면이었다. `GUARANTEES` 는 성공한 task 의 receipt 와 inspect summary 에만 붙는데, 설치 절차가 `install-skills` 다음에 `doctor` 를 부르므로 사람이 이 도구를 믿을지 정하는 첫 화면은 `doctor` 다. 상쇄해야 할 신호보다 상쇄가 늦게 오면 안 된다. 코드 상수 `DOCTOR_SIGNALS`(verification/sandbox/signatures)를 프로바이더 줄 뒤에 append-only 토큰 한 줄로 낸다. 39 와 같은 이유로 산출값이 아니라 상수이며 기계 표면이라 언어 설정과 무관하다. 기전 존재를 주장하는 `verification: flags-mentioned` 는 실제 동작 테스트에 묶고, `sandbox: none` 과 `signatures: not-checked` 는 doctor 가 샌드박스를 만들거나 서명·해시를 확인하지 않는다는 소스 단언에 묶는다. 27 의 실패 봉투는 여기서도 넓히지 않는다.

43. `inspect` 는 provider·credential·timeout·launch 를 일부러 만지지 않는다. 그래서 "지금 무엇이 어디로 나가려 하는가" 한 장이 비어 있었다. task 의 `--preview` 는 같은 pipeline 으로 packet 을 만들고 검증한 뒤 영수증에 provider mode·credential source 종류·`--max-bytes` 잔여·`launch: not-started` 를 더해 출력하고 **벤더를 실행하지 않는다.** 자격증명은 존재만 보고 값을 읽지 않는다. 값을 읽으면 미리보기가 실행만큼 위험해진다. 대장은 남기지 않는다. 한 줄은 egress 지점 도달을 뜻하는데 미리보기는 거기에 도달하지 않으며, 나가지 않은 것이 섞이면 "무엇이 나갔나" 라는 대장의 질문이 무의미해진다. `--dry-run` 과 함께 쓰면 usage 거절이다. `--dry-run` 은 패킷 본문을 내고 `--preview` 는 절대 내지 않으므로 둘 중 하나를 조용히 고를 수 없다. 39 의 성공 표면 규약대로 `guarantees` 를 싣고 27 의 실패 봉투는 넓히지 않는다.

44. 추론 깊이는 노브가 없어 벤더 기본값에 맡겨져 있었다. 실측하니 같은 패킷·같은 질문에서 `low` 108초 `medium` 214초 `high` 444초 `max` 751초로 `high` 까지는 한 단계마다 약 2배(1.98, 2.07)였고 `max` 로는 1.69 로 완만해졌으며, 53KB 패킷에서도 `low` 146초 `max` 903초로 배수가 유지됐다. 반대로 effort 를 고정하면 바이트가 20배 늘어도 1.20~1.35배뿐이다. `--effort {low,medium,high,xhigh,max}` 를 연다. 열거값이라 argv 주입 표면이 없고 생략하면 플래그를 넣지 않아 벤더 기본값이 쓰인다. 값과 출처는 `timeout_seconds` + `timeout_source` 선례대로 나눈다. 고르지 않으면 `effort` 는 null 이고 `effort_source` 가 `vendor-default` 다. 한 필드에 섞으면 enum 도메인에 sentinel 이 들어가고 출처가 늘어날 때 값 도메인을 깨야 한다. auto timeout 은 크기 tier 와 effort tier 중 **큰 값**을 쓴다. effort 가 크기 tier 를 끌어내리면 큰 패킷 상한이 조용히 낮아지는 회귀다. low/medium 1200, high 1800, xhigh/max 2700 이며 관측 최악 903초에 3배 안팎 여유다. `xhigh` 는 재지 않았고 high 와 max 사이일 것이므로 보수적으로 max 와 묶었다. `PACKET_ASK_EFFORT` 가 기본값을 준다. 우선순위는 플래그 > env > 벤더 기본값이고 `effort_source` 가 `explicit`/`env`/`vendor-default` 로 남는다. 출처 기록이 기본값과 조용한 기본값을 가른다. env 값은 별도로 검증한다. argparse choices 는 플래그만 보므로 여기서 안 막으면 오타가 조용히 벤더 기본값으로 떨어진다. 빈 값은 설정하지 않음이다. 프로바이더 검증은 해석된 값을 본다. 플래그 경로만 막으면 env 가 우회로가 된다. env 는 모든 task 실행에 걸리므로 설정한 채로 paste 를 부르면 거절된다. 플래그와 일관되지만 변수는 잊기 쉬우니 문서에 적는다. `EFFORT_LEVELS` 와 tier dict 는 집합이 같아야 한다. 레벨만 늘리면 그 레벨의 deadline 이 조용히 크기 tier 로 떨어진다. `build_receipt` 는 값과 출처를 required 로 받고 어긋난 조합을 거절한다. Claude 계열(glm, claude)만 이 노브를 갖고 paste·kimi 는 usage 로 거절한다. 조용히 버리지 않는다. effort 는 receipt·JSON·대장·`--preview` 에 전부 실린다. 39 의 성공 표면 규약이고 27 의 실패 봉투는 넓히지 않는다.
45. 시크릿 이름 추정(`_SECRET_SEGMENT_RE`)만 사용자 allowlist 로 면제할 수 있다. 확장자·이름 규칙과 `.env` 접두는 자격증명 파일의 정의라 면제 대상이 아니고 먼저 검사한다. 면제는 정확한 워크트리 상대경로로만 적고 글롭을 받지 않으며, 파일이 없으면 빈 집합이지만 모양이 어긋나면 벤더를 실행하지 않고 거절한다. 영수증과 inspect summary 는 이번 패킷에서 실제로 쓰인 면제 수를 `secret_name_exempt_used` 로 공개한다.

46. 감독 프로세스가 제한 환경을 전달하는 코드 전용 훅을 둔다. `paths.set_confined_env_hooks` 로 자식·git 환경의 추가값만 등록하고, 사용자 TOML·CLI·환경 변수 표면은 열지 않는다. 훅이 줄 수 있는 이름은 allowlist다. 자식은 감독 프록시 8종(HTTP_PROXY·HTTPS_PROXY·ALL_PROXY·NO_PROXY 대소문자), git은 DEVELOPER_DIR만이다. denylist는 로더 주입 계열 키를 빠뜨리면 격리가 약해지므로 쓰지 않는다. 값 검증은 하지 않는다. 훅은 in-process 코드라 값의 책임은 호출자에게 있다. 훅 실패는 격리 초기화 실패라 confinement 로 벤더를 막는다. Claude 전용 tmp 변수는 제품이 격리 TMPDIR 로 고정한다. 외부 어댑터가 함수 참조 여러 곳을 monkeypatch하는 대신 이 한 점만 거치도록 두며, 제품 버전이 바뀌면 외부 어댑터의 버전 확인과 함께 재검증한다. 부모 환경 복사를 열지 않는다.

47. 보호 여부는 적용 상태만 표시하고 보장으로 선언하지 않는다. receipt·inspect 요약·대장·`--preview`·`doctor` 에 `supervision: none|external` 을 additive 로 싣는다. `external` 은 영수증 빌드 시점에 코드 훅이 등록돼 있었다는 뜻이고, OS 격리를 검증했다는 뜻이 아니다. 빈 훅도 external이므로 효과 아님을 문서에 고정한다. 실행기 존재만으로 바뀌지 않으며 `sandbox: none` 상수와 함께 읽는다. 보호 호출 자체는 외부 실행기와 스킬이 glm 으로만 고른다. `is_protected_provider` 가 그 선택 계약을 코드로 말하지만, 제품 CLI에 보호 모드가 없어 강제 지점은 없고 supervision 표시는 provider와 무관한 호스트 상태다. kimi·claude 실행에도 훅이 있으면 external이 실리므로, 그것을 보호 검증으로 읽지 않는다. CLI 플래그는 열지 않고 스킬 분기로만 둔다. 27 의 실패 봉투는 넓히지 않는다.
48. 출력 쪽 지시문 탐지는 기전이 있는데 기계 표면에 대응 키가 없었다. 벤더 응답은 nonce 불신뢰 봉투로 감싸고 본문 안의 봉투 구분자를 무력화한 뒤, 지시문 유사 문구를 목록으로 훑어 걸리면 머리줄에 한 문장을 더한다. 그 목록은 세 문장뿐이다. 그래서 "`--outside-surface` 를 쓰라" 같은 **정상 리뷰형 제안**은 표시 없이 지나가고, 목록에 없는 언어·우회 표현도 지나간다. 필터가 아니라 트립와이어다. 대조는 대소문자를 가리지 않는 부분문자열 검사라 정상 답변이 그 문구를 인용·에코해도 표시가 붙는다. 오탐 방향도 문서에 같이 적는다. 39 의 성공 표면 규약대로 `guarantees` 에 `output_screen: lexical-tripwire` 를 additive 로 싣고 값을 질문 쪽 `policy_gate` 와 같은 어휘로 둔다. 다만 집행은 다르다. `policy_gate` 는 걸리면 요청을 거절하지만(exit 10) `output_screen` 은 한 문장을 더할 뿐 응답을 그대로 전달한다. 값 어휘가 같다고 집행이 같다고 읽지 않는다. 기전 존재를 주장하는 키이므로 상수만 고정하지 않고 목록의 각 문장이 실제로 발화하는지, 발화해도 본문을 지우지 않는지, 그리고 표시가 **붙지 않는** 정상 문장을 함께 테스트로 묶는다. 목록을 늘리려면 그 테스트와 문서를 같이 고쳐야 한다. 봉투는 출력을 실행해도 안전하게 만들지 않으며, MAIN 이 봉투 안 텍스트를 지시로 취급하지 않는 것은 이 도구의 통제가 아니라 호스트 쪽 규약이다. 봉투를 거치는 지점은 하나로, task 를 마무리하는 한 곳에서 모든 프로바이더 경로가 만나고 task stdout 으로는 그 결과만 나간다. JSON 봉투에도 같은 값이 `untrusted_output` 로 실린다. paste 는 벤더를 띄우지 않지만 같은 지점을 지난다. 27 의 실패 봉투는 넓히지 않는다.

49. `install-skills` 는 한 홈의 실패로 나머지를 막았다. 정확히는 all-or-nothing 이 아니라 **보고 없는 부분 설치**였다. 홈을 순서대로 시도하다 첫 실패에서 예외를 던졌는데, 그 시점까지 쓴 홈은 이미 쓰여 있고 반환 목록은 통째로 사라져 CLI 가 한 줄도 출력하지 않았다. 실측: 두 번째 홈이 심링크면 첫 홈은 쓰인 채 exit 13, 보고 0줄, 나머지 두 홈은 낡은 SKILL.md. 사용자는 무엇이 설치됐는지 알 수 없어 나머지 홈의 낡은 스킬을 새것으로 오해한다. 홈별로 진행하고 실패를 모은다. 가드는 그대로다 — 심링크 구성요소 거절과 `--force` 없는 다른 내용 보호는 홈 단위에서 여전히 fail-closed 다. 모으는 실패는 가드 실패만으로 한정하지 않는다. 읽기·쓰기 실패(OSError)와 non-UTF-8 로 저장한 기존 SKILL.md 도 홈 단위 가드 실패로 바꾼다. 바꾸지 않으면 그 예외가 그대로 새어 나와 트레이스백이 되고 나머지 홈은 시도되지 않아 고치려던 그 상태가 다시 난다. 실측으로 두 경로 모두 재현했다. 읽지 못한 기존 파일은 원문과 같다는 것을 증명할 수 없어 덮지 않으며 이 분기는 `--force` 를 보기 전에 오므로 usage 가 아니라 confinement 다. 사유는 렌더된 문장이 아니라 **메시지 카탈로그 키**로 모은다. 문장을 담으면 실패 시점의 언어 설정이 보고에 굳고, 미래의 메시지가 경로를 보간하기 시작해도 보고서 쪽에서 막을 수 없다. 등록되지 않은 키는 거절된다. 설치된 경로는 stdout, 실패는 홈 상대경로와 카탈로그 사유 문장으로 stderr 에 한 줄씩 낸다. 이미 원문과 같던 홈은 다시 쓰지 않지만 설치된 것으로 보고된다 — "쓴 경로"가 아니라 "실행 뒤 최신인 경로"다. 종료 코드는 confinement 가 usage 보다 무겁다. `--force` 를 더해도 해결되지 않는 실패가 남았다는 뜻이기 때문이다. 그 밖에는 첫 실패의 코드를 그대로 쓰고, 새 실패 종류가 usage 로 뭉개지지 않게 코드를 매핑하지 않는다. 여기서 13 은 설치 중 격리 검사 실패지 "벤더를 시작하지 않았다" 는 10–14 의 뜻이 아니므로 README 가 그 차이를 적는다. 홈 **사이**는 독립적이다. 한 홈의 성공·실패가 다른 홈의 시도를 막지 않는다. 홈 **안**의 원자성은 주장하지 않는다. 쓰기는 truncate-and-write 지 temp+rename 이 아니므로, 쓰는 중에 죽으면 잘린 SKILL.md 가 남고 다음 실행은 그것을 다른 내용으로 봐 `--force` 없이 덮지 않는다. 홈 사이 트랜잭션도 없다 — 네 홈 전부 성공 또는 전부 무효를 보장하지 않으며 그 상태는 stderr 보고로 드러난다. 롤백을 만들지 않은 이유는 되돌리기가 사용자 원본을 덮는 길이기 때문이다.

50. 정책 게이트의 우회로를 게이트 자신이 말한다. 이 게이트는 어휘 트립와이어고 우회로는 표현 바꾸기다. 목록은 MIT 소스의 정규식 두 개이므로 "공개하면 우회가 쉬워진다"는 반론은 성립하지 않는다 — 이미 공개돼 있다. 그런데 우회로와 오탐 방향은 SECURITY 한 줄과 `guarantees.policy_gate: lexical-tripwire` 에만 있었고, **걸린 사람이 보는 유일한 표면인 거절 메시지에는 없었다.** 문서를 읽지 않는 사람이 게이트를 만나는 지점이다. 두 계열 거절 문장 뒤에 고정 한계를 붙인다. 질문 원문과 매치 위치는 회신하지 않는다. 되돌려 주면 질문이 stderr 와 실패 봉투에 다시 등장한다. 단 계열 문장 **자체가** 목록 단어를 담는다(운영 사고 계열의 "Production incident"). 그래서 주장하는 것은 "목록 단어가 메시지에 없다"가 아니라 "사용자 질문을 싣지 않는다"다. 오탐은 재현했다: `구현해 주지 말고 검토만 해라`, `코드를 작성하지 말고 분석만 해줘`, `Do not implement this, just review it`, `don't fix this bug, just review it` 이 전부 exit 10 이다. 열어 둘 수 없는 이유도 재현했다: 부정어를 보는 규칙을 넣은 뮤테이션에서 `구현하지 말고 이 버그를 고쳐줘`와 `이 버그를 고치지 말고 구현해줘`가 함께 통과했다. 둘은 실제로 수정·구현을 시키는 문장이다. 창·절 단위로 표현 가능한 정규식 규칙은 이 둘을 오탐 셋과 구분하지 못한다. `구현하지 말고 이 버그를 고쳐줘`(부정된 동사 + 실제 요청)와 `구현해 주지 말고 검토만 해라`(부정된 동사 + 검토 요청)가 같은 형태이기 때문이다. 그래서 `_IMPLEMENTATION_RE` 에 부정문 처리를 넣지 않는다. 덮는 범위가 고르지 않은 것도 실측했다 — `이 diff를 구현하지 말고 보안 관점에서 검토만 해줘` 는 목록에 없는 형태라 통과한다. 같은 뜻의 문장이 한쪽은 걸리고 한쪽은 지나가는 것이 어휘 게이트의 실제 모양이고, 이 비대칭을 테스트로 고정해 목록을 좁히거나 넓히는 판단이 전체 모양을 보고 이뤄지게 한다. 이 절이 실제로 났다: 이 변경의 리뷰 요청 자체가 질문 본문에 계열 단어를 담아서 exit 10 으로 막혔고, 표현을 바꾼 뒤에야 나갔다. 27 의 실패 봉투는 넓히지 않는다. 봉투의 code/kind/message 세 키는 그대로이고 메시지 **카탈로그**에 `policy_lexical_limit` 하나가 늘었다. 둘을 같은 "키"로 부르면 카탈로그가 늘지 않았다고 읽힌다.

51. 대장은 "무엇이 나갔나" 만 답했다. 무엇이 돌아왔는지·답이 왔는지는 기계 표면이 0 이었고, 그 공백을 네 출처가 독립적으로 짚었다. 응답 쪽 줄을 같은 파일에 `phase` 로 갈라 추가한다. `egress` 는 런치 전에, `result` 는 응답이 확정된 뒤에 쓴다. 같은 파일을 쓰는 이유는 경로 검증 장치(절대경로, device+inode 워크트리 검사, `O_NOFOLLOW`, 0600 강제)를 두 번 만들지 않기 위해서다. 두 phase 가 하나의 append 경로를 공유하므로 검증이 공짜로 같이 적용된다. 짝 짓는 키는 packet digest 다. 새 실행 식별자를 만들지 않는다 — 같은 패킷을 두 번 보내면 두 쌍이 생기고 그것이 실제 일이기 때문이다. 대신 읽는 규칙을 명시한다: digest 와 시각 순서로 짝짓고, 같은 패킷을 **동시에** 두 프로세스로 보내면 interleaving 해서 파일만으로 짝을 정할 수 없다. 런 락은 Kimi 전용이므로 glm 동시 실행은 막히지 않는다. 결과 줄은 timestamp·phase·mode·provider·digest·outcome·output_bytes·output_hint, 실패했을 때만 failure_code 를 담는다. `selector` 와 `paths` 는 결과 줄에 없으므로 읽는 쪽은 모르는 phase 를 건너뛰어야 한다. 질문·파일 본문·벤더 답변·벤더 stderr 는 어느 줄에도 싣지 않는다. `answered` 는 출력 가드를 통과한 응답이 돌아왔다는 뜻이지 exit 0 이라는 뜻이 아니다(cleanup 경고는 뒤에 올 수 있다). `output_bytes` 는 봉투에 실제로 들어가는 본문, 즉 rstrip 뒤·프레임 제외 크기다. rstrip 전을 재면 사용자가 보는 본문보다 큰 값이 기록된다. `not-observable` 은 벤더를 띄우지 않는 provider mode 다 — 지금은 paste 이고 `--dry-run` 도 provider 를 paste 로 강제해 같은 경로를 탄다. 답이 이 도구를 지나지 않으므로 echo 되는 패킷 본문을 output_bytes 로 기록하지 않는다. 기록하지 않으면 paste 실행과 크래시가 대장에서 같아지므로 줄은 쓴다. `output_hint` 는 48 의 트립와이어 발화 사실만 남기고 문구는 남기지 않는다. 발화 여부는 봉투 문자열에서 다시 찾지 않고 봉투를 만드는 곳에서 같이 반환한다. 문자열 검색으로 되찾으면 벤더가 그 문장을 에코했을 때 오판한다. 어긋난 조합(answered 아닌데 output 필드가 채워짐, failed 인데 failure_code 없음)은 `build_receipt` 의 effort 검사처럼 ValueError 로 거절한다. 그 검사는 결과 쓰기 try **밖에** 둔다. I/O 실패가 아니라 호출자의 프로그래밍 오류이므로 경고로 삼키면 둘이 구별되지 않는다. 결과 줄 쓰기 실패는 egress 와 **대칭이 아니다**. egress 는 기록 실패 시 벤더를 띄우지 않는다 — 아직 아무것도 나가지 않아 되돌릴 수 있기 때문이다. 결과 줄 시점에는 이미 나갔고 답도 손에 있으므로, opt-in 기록 때문에 답을 버리는 쪽이 더 큰 손실이다. 고정 경고를 stderr 에 남기고 실행은 성공으로 끝낸다. "조용히 빠뜨리는 대장은 없느니만 못하다" 는 규칙은 egress 쪽 규칙이고 여기서 경고가 그 역할을 한다. 그래서 **result 줄이 없는 egress 줄은 세 가지 뜻이 겹친다**: 죽임당한 실행, 처리된 오류 경로 밖의 죽음, 결과 기록 실패. 마지막만 stderr 경고가 남고 파일에서는 셋이 구별되지 않는다. 이 잔여를 문서에 적는다. 0.11.0 이전 줄에는 `phase` 가 없고 전부 egress 로 읽는다. preview 와 inspect 는 egress 에 도달하지 않으므로 어느 줄도 남기지 않는다. dry-run 은 남긴다 — 처음에는 남기지 않는다고 적었는데 실측하니 egress 와 result 가 다 남았고, stdout 이 paste 와 같은데 대장만 다르면 같은 행동이 두 가지로 기록되므로 동작이 맞고 문장이 틀렸다. 27 의 실패 봉투는 넓히지 않는다.

52. 대장은 쓰기 전용이었다. 사람이 "지금까지 무엇이 나갔나" 를 물으려면 JSONL 을 직접 읽어야 하고, 그 파일에는 상대경로가 줄마다 들어 있다. 읽기 표면을 연다: `packet-ask ledger summary`. 집계만 반환하고 경로·질문·본문은 옮기지 않는다. 대장에 무엇이 들었는지와 요약이 무엇을 보여주는지를 일부러 다르게 둔다 — 감사 질문은 "얼마나, 얼마나 자주, 답이 왔나" 지 "어떤 파일이었나" 가 아니다. 파일을 읽으려면 그 파일을 쓰던 사람이면 되고, 요약은 카운터라 화면·로그에 옮겨도 내용이 따라가지 않는다. 경로는 `PACKET_ASK_LEDGER` 가 유일한 출처다. 인자로 경로를 받지 않는다 — 받으면 대장이 아닌 임의 파일을 이 명령으로 읽게 되고, 쓰기 쪽과 출처가 갈라진다. 없으면 usage(2) 다. **파일은 만들지 않는다.** 읽기 표면이 파일을 만들면 켜진 적 없는 대장이 생긴다. 읽기의 격리 검사는 쓰기와 **같지 않다**: 절대경로, `O_NOFOLLOW`, 일반 파일, 현재 사용자 소유 넷은 같지만 파일 모드는 강제하지 않고 워크트리 내부 검사도 다시 하지 않는다. 모드를 강제하면 "읽기는 고치지 않는다" 가 거짓이 되고, 사용자가 일부러 풀어 둔 모드를 조용히 바꾼다. 쓰기가 append 마다 0600 을 강제하므로 이 도구가 쓴 대장은 0600 이고, 나중에 풀린 경우는 요약과 무관하게 이미 노출 상태라 읽기가 노출을 넓히지 않는다. 워크트리 검사를 안 하는 이유는 "쓰는 쪽에서 이미 거절했다" 가 아니다 — 대장 위치에 나중에 `git init` 이 되거나 디렉터리가 옮겨질 수 있다. 진짜 이유는 그 검사의 위협 모델이 읽기에 적용되지 않기 때문이다. 검사가 막으려는 것은 대장이 packet 범위로 들어가 벤더로 따라나가는 것이고, 요약은 파일 내용을 어떤 패킷에도 싣지 않는다. 상한(8 MiB)을 넘으면 접두어만 요약하지 않고 budget(14) 으로 거절한다. 부분 요약은 전체로 읽힌다. 해석 못 하는 줄과 모르는 phase·outcome 은 `skipped` 로 세고 계속한다. 한 줄 때문에 감사 표면을 못 쓰면 안 되고, 반대로 조용히 버리면 대장이 잘렸는지 알 수 없다. 읽기는 파일 내용을 **다시 신뢰한다.** 손으로 고쳤거나 동기화로 섞인 줄일 수 있으므로, 화면에 그대로 보간되는 timestamp 는 쓰기 쪽 고정 형식과 맞을 때만 받고 카운터에 더할 byte 값도 형을 본다. 맞지 않으면 그 줄은 해석 불가로 넘긴다. 억지로 세면 카운터가 조용히 틀리고, 그대로 보간하면 한 줄 토큰 계약과 터미널 상태가 깨진다. 별칭 라벨의 제어문자 거절과 같은 출력 규율이다. `phase` 가 없는 줄은 egress 로 세므로 0.11.0 이전 파일도 요약된다. 짝은 digest 별로 세고 차이는 `unpaired_egress` 에 남긴다 — 51 의 결과 없는 egress 세 가지 뜻이 여기서 숫자가 된다. digest 가 없는 줄은 짝짓지 않는다. 빈 키 한 버킷으로 모으면 digest 없는 egress 와 result 가 서로를 상쇄해 짝이 있는 것처럼 보이므로, 짝을 지을 수 없으면 짝이 없다고 말한다. 사람 줄은 영수증과 같은 append-only 토큰 나열이고 provider 목록은 의도적으로 싣지 않는다. 사용자 별명이 공백을 담으면 토큰 분리가 깨지므로 기계 판독은 JSON 쪽에 둔다. 27 의 실패 봉투는 넓히지 않는다 — 상한 초과도 그 봉투로 나간다.

53. 재검증 실패는 종류만 말하고 위치를 말하지 않았다. `Sensitive data remained after verification: phone` 과 exit 12 가 전부라, 여러 파일을 골랐으면 어느 것인지 알 수 없고 scrub 이 못 지우는 형태는 **영구 실패**이므로 사용자에게는 원문을 고치는 것 말고 길이 없는데 어디를 고쳐야 하는지도 없었다. 실패 지점을 국소화한다. verify 가 실패했다는 것은 잔여 매치를 이미 찾았다는 뜻이므로 이것은 새 탐지가 아니라 **이미 계산한 것의 보고**다. 위치 라벨은 세 종류다: `question`, 항목의 패킷 상대경로, `changes.patch`. 라벨을 싣는 것은 사람이 보는 stderr 메시지뿐이고, 27 의 JSON 실패 봉투는 코드별 고정 문장만 쓰므로 경로를 직렬화하지 않는다. 그 경로는 사용자가 `--files` 로 고른 값이고 영수증에 이미 실리는 것과 같은 부류이며, exit 12 는 egress 가 차단된 상태라 로컬을 벗어나지 않는다. 종류는 렌더된 문장에서 파싱해 되찾지 않고 예외가 구조로 나른다 — 문구가 바뀌면 조용히 깨진다. **줄 번호는 보고하지 않는다.** verify 는 공백·하이픈·괄호를 텍스트 전체에서 지운 뒤 훑으므로 잔여가 여러 줄에 걸쳐 만들어질 수 있고, 실측한 두 입력(`010-1234.` + 줄바꿈 + `5678`)은 전체 검증에서 막히는데 **어느 한 줄도 단독으로는 걸리지 않는다.** 없는 위치를 가리키는 것보다 항목 단위가 정직하다. 조립 단계 검증은 따로 말하고, 항목별 검증은 그보다 먼저 끝나므로 조립 실패의 원인은 항목 본문 밖에 있다는 것이 구조적으로 참이다. 실측 사례: 본문이 `print(1)` 인 파일이 파일명 `010-1234.5678.py` 하나로 exit 12 가 된다. 파일명은 헤더로 `packet.md` 에 실리지만 항목 본문 검증은 그것을 보지 않는다. 같은 문장으로 보고하면 사용자는 본문을 뒤지고 아무것도 못 찾는다. 그래서 조립 실패는 프레이밍과 항목 결합을 보라고 말한다. 이 국소화는 영구 실패의 탈출구다. 시장 선례도 같은 모양이다 — repomix 는 의심 파일을 제외하고 **파일명을 사후 보고**한다. 27 의 실패 봉투는 넓히지 않는다.

## 금지

구현·패치 적용, `--all`, 워크트리 밖, 커스텀 HTTP, 전역 `ANTHROPIC_BASE_URL` 변경, 워커 팜.
