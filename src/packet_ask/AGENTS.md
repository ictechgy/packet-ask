# 구현 규약

`src/packet_ask/` 아래에서 활성화된다. 루트 [AGENTS.md](../../AGENTS.md) 를
먼저 읽는다.

## 실행 경계

동작을 바꾸면 [docs/design.md](../../docs/design.md) 의 번호 매긴 불변식도
같이 고친다. 그 목록이 이 패키지의 실제 계약이다.

핵심 순서는 **scope → scrub → verify → budget → receipt → launch → cleanup**
이다. 이 순서를 뒤집는 변경은 하지 않는다.

## fail-closed

- 확신이 없으면 **벤더를 실행하지 않는 쪽**을 고른다.
- 스크럽 재검증이 실패하면 벤더를 실행하지 않는다. 경고로 강등하지 않는다.
- 조용한 기본값을 만들지 않는다. 사용자가 준 값이 쓸 수 없으면 거절한다.
  빈 `--provider` 를 `paste` 로 떨어뜨리거나 `--include-files` 를 말없이
  버리는 것이 과거의 실제 결함이었다.
- 영수증의 `selector` 는 **실제로 보낸 범위**와 항상 일치해야 한다.

## 비밀 값과 출력

- 키, 패킷 경로, raw argv, 예외 원문, traceback 을 로그·영수증·JSON·타이밍에
  넣지 않는다.
- `--json` 실패 봉투는 `schema` / `ok` / `error(code, kind, message)` 세 키만
  담는다. 넓히지 않는다.
- 성공 표면(receipt, inspect summary)에는 `receipt.GUARANTEES` 상수가 실린다.
  이것은 산출값이 아니라 코드 상수다. 기전 존재를 주장하는
  `redaction` / `doctor` / `policy_gate` 값은 실제 동작 테스트에 묶여 있으니
  구현을 바꾸면 그 테스트도 같이 본다.
- `doctor` 출력 끝에는 `doctor.DOCTOR_SIGNALS` 상수가 한 줄로 붙는다. 같은
  이유의 같은 규약이다. `verification` 은 기전 존재 주장이라 동작 테스트에,
  `sandbox` / `signatures` 는 doctor 가 그것을 하지 않는다는 소스 단언에
  묶여 있다.
- `packet-ask.v1` 은 additive 다. 키를 더할 수는 있어도 지우거나 이름을
  바꾸지 않는다. 사람이 읽는 영수증 한 줄도 append-only 토큰 나열이다.

## egress 표면과 비-egress 표면

`ledger` 한 줄은 **egress 지점에 도달했다**는 뜻이다. 전달 확인이 아니라
도달이고, 그래서 벤더가 그 뒤에 실패해도 줄은 남는다. 이것이 안전한 방향이다.

벤더를 실행하지 않는 경로(`inspect`, `--preview`, `--dry-run`)는 **대장을
남기지 않는다.** 나가지 않은 것이 섞이면 "무엇이 나갔나" 라는 대장의 질문
자체가 무의미해진다. 새 표면을 만들 때 분기를 `append_ledger_entry` **앞**에
두는지 확인한다.

같은 이유로 비-egress 표면은 자격증명 **값을 읽지 않는다.** 존재 확인까지만
한다. 값을 읽으면 미리보기가 실행만큼 위험해진다.

뜻이므로 그 의미를 깨지 않는다.

## 메시지 카탈로그

- 사용자에게 보이는 문자열은 전부 `text.py` 의 `_EN` / `_KO` 에 넣고
  `message(key)` 로 꺼낸다. 문자열을 코드에 직접 쓰지 않는다.
- 두 카탈로그의 키는 같아야 한다. `message()` 가 `_EN` 으로 폴백하므로
  누락이 조용히 영어로 새어 나온다.
- 메시지에 경로·키·사용자 입력을 넣지 않는다. 고정 문장으로 쓴다.

## 레지스트리와 확장점

- builtin provider adapter 와 credential backend 는 **immutable 코드
  레지스트리**다. 사용자 설정으로 등록하는 길을 열지 않는다.
- 사용자 `providers.toml` 은 paste 별명만 받는다. `executable`, `argv`,
  `env`, `command` 같은 키는 거절한다.

## 코드 스타일

- 함수 하나는 역할 하나. 본문 10줄을 목표로 하고 넘으면 분리를 검토한다.
- 함수·타입에 한국어 문서화 주석을 단다. **무엇을 하는가만이 아니라 왜
  이렇게 하는가**를 적는다. 이 패키지의 주석은 대부분 위협 모델을 설명한다.
- 축약 없는 이름을 쓴다. Boolean 은 `is`/`has`/`should`/`can` 접두사.
- 빈 `except` 를 두지 않는다. 오류를 삼키지 않는다.

## 자주 틀리는 것

- `subprocess.communicate()` 로 select 드레인을 바꾸지 말 것. 출력이 커지면
  버퍼가 불어난다.
- 자식 환경은 `os.environ.copy()` 가 아니라 `minimal_child_env` 화이트리스트다.
- `os.write` 는 짧게 쓸 수 있다. 전부 쓸 때까지 루프를 돈다.
- `O_CREAT` 의 mode 는 **생성 때만** 적용된다. 기존 파일 권한은 따로 강제한다.
- 경로 포함 관계를 문자열 `relative_to` 로 판정하지 말 것. macOS 기본 APFS 는
  대소문자를 구분하지 않아 조용히 뚫린다. device·inode 로 본다.
- 할당문 리댁션을 공격적으로 바꾸면 **소스 코드를 파괴한다.** 리터럴 패턴만.
- `scrub` 과 `verify` 는 **일부러 넓이가 다르다.** verify 가 더 넓은 것은
  설계다. 완전히 같으면 놓친 형식을 같이 놓친다. 다만 scrub 이 지울 수 없는
  형식을 verify 만 잡으면 그 패킷은 **영영 못 나간다.** 사용자에게 원문을
  고치는 것 말고 길이 없다. verify 쪽을 넓힐 때는 scrub 이 그것을 지울 수
  있는지 같이 본다.
- verify 는 공백·하이픈·괄호를 **텍스트 전체에서** 지운 뒤 훑는다. 무관한
  숫자들이 붙으므로 새 숫자 패턴에는 `(?<!\d)`/`(?!\d)` 경계를 넣는다.
  git diff 의 `index <old>..<new> 100644` 가 실제로 전화번호로 오탐됐다.
